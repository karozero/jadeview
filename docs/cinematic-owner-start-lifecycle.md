# Cinematic owner start lifecycle (source audit)

## Finding

A BF archive can identify the script owner, its AI instance/model, serialized callback slots, owner-local variables and linked EVE resources. That is enough to **resolve** the likely callback and event chain by resource keys. It is not enough to prove that the game would activate the object or start the cinematic in a particular playthrough.

The engine does not simply execute every loaded object's init function. It dispatches callbacks from several runtime paths, and `Cine_Events` applies saved-state, actor, collision, capability, priority, input and delay gates before it starts its event tracks. Therefore an automatic generic init callback is not safe to run in JadeView. Static owner/callback discovery is safe; arbitrary callback execution is not.

## Source-derived lifecycle

1. **Object load creates references, not a running script.** The PC object loader reads an AI instance reference when serialized GAO flag `0x20` is present and an EVE event-list reference when `0x02000000` is present ([`gameobject.c`](../external/irisEng/gameobject.c#L3085-L3107)). `WOR_World_JustAfterLoadObject` resolves the AI instance and EVE links and attaches the object to the world; it does not execute the script init function ([`world.c`](../external/irisEng/world.c#L1060-L1085)).

2. **AI loading establishes the effective static callback table.** An AI instance points to its model and variable resource ([`ai_common.c`](../external/irisEng/ai_common.c#L1387-L1408)). The variable resource stores five callback function references and a separate list of instance functions ([`ai_common.c`](../external/irisEng/ai_common.c#L1292-L1322)). During instance reinitialization, the engine copies non-null model callbacks into the instance callback table and resets callback timing; instance values are restored from the instance/default data ([`ai_common.c`](../external/irisEng/ai_common.c#L375-L443)). This is a deterministic, key-based relationship that does not need sibling-name guesses.

3. **Callback execution is selected by engine context.** `AI_ExecCallback` runs the model callback at the requested callback ID and any dynamically registered callback entries with that same ID ([`ai_common.c`](../external/irisEng/ai_common.c#L812-L878)). The source dispatches different IDs from render, animation and the engine frame loop: Iris uses IDs 0/1 during geometry display, ID 3 from animation, and `AI_ExecCallbackAll(world, 2)` from the frame loop ([`geo.c`](../external/irisEng/graphicsobjects/geo.c#L758-L780), [`geo.c`](../external/irisEng/graphicsobjects/geo.c#L879-L895), [`animation.c`](../external/irisEng/animation.c#L2391-L2391), [`engine.c`](../external/irisEng/engine.c#L283-L295)). The later Jaded source confirms the callback names for slots 0-3 (`BeforeDisplay`, `AfterDisplay`, `AfterRec`, `AfterBlend`) ([`AIstruct.h`](../external/jaded/src/libraries/AIinterp/Sources/AIstruct.h#L50-L58)). A loaded callback slot is therefore evidence of availability, not evidence it has run.

4. **`Cine_Events` is a state machine with a start predicate.** In the BGE-specific compiled script, `cine_firstinit` enters `cine_init` immediately or after its configured first delay ([`ai_compiledscripts_global_managers.c`](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L4029-L4058)). `cine_init` schedules `cine_tests_depart` ([same source](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L4380-L4389)). That test callback checks the owner capability `0x100`, special save-flag bits, configured actor/model and collision-overlap conditions, then readiness, priority/interruption and custom state before proceeding ([same source](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L4554-L4650), [later gates](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L5385-L5456)). Some references encode `AI_MainActor` indices rather than a fixed GAO, so resolving them requires current player/companion assignment. The source also reads global saved flags (`Flag_speciaux_sauve`) and performs collision queries; these are not facts recoverable from the cinematic container alone.

5. **Start mutates runtime state before playing tracks.** `Cine_Events_Cine_exec_InitialiseCine` evaluates saved special flags and applies global/UI/input/camera/audio changes ([same source](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L5706-L5838)). `GoToEvents` sets the owner to playing, initializes elapsed time, starts all owner EVE tracks and switches its AI callback to `cine_play_eventtrack` ([same source](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L5841-L5898)). This is not a pure initializer.

6. **Playback can end by timeout or owner-bit interruption.** `GoToEvents` stores `des_f_duree_totale` in the elapsed timer, using `1.0e14f` when the configured duration is zero. The playback callback decrements that timer and calls `TRAStopAll` when it expires or owner custom bit `0x4000` is clear ([source](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L5891-L5898), [playback stop check](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L5962-L6005)). JadeView's explicit owner-start preview now applies the finite timeout to all tracks of that owner, including `RunningInit` tracks. It does not yet infer early termination from `0x4000`: that bit can be changed by other scripts or runtime callbacks not present in the resolved preview timeline.

The interrupt callback can clear `0x4000` through two source paths: the priority check can mark this owner inactive when another cinematic owns the active slot, or the enabled exit predicates can all pass. The exit mask uses `0x01` for the configured exit collision relation, `0x04` for an actor activity comparison, `0x08` for a capability-mask comparison, and `0x80` for a saved special-flag polarity test ([interrupt callback](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L5470-L5650), [priority callback](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L5652-L5705)). Collision results, active actors, capability state, save flags and competing-cinematic ownership are runtime inputs. Therefore JadeView can expose the configured exit fields, but cannot safely predict their pass time from the archive alone.

7. **EVE is advanced only for a scheduled world and an eligible owner.** The outer engine loop walks universe-world entries and calls `ENG_OneWorldEngineCall` only when the slot's active bit is set ([`engine.c`](../external/irisEng/engine.c#L540-L582)); a world can be loaded and have its object/EOT tables built while its universe slot remains inactive ([`world.c`](../external/irisEng/world.c#L2243-L2261)). Within a scheduled world, `EVE_MainCall` iterates the event-object EOT table and requires a valid owner with an EVE component, a passed distance gate when enabled, and runtime `flags2` bit `0x00400000` clear ([`events.c`](../external/irisEng/events.c#L2683-L2723)). `TRAPlayAll` only sets the running bit on those tracks ([`ai_eventtrackfunctions.c`](../external/irisEng/ai/ai_eventtrackfunctions.c#L5-L18)); EVE's runner processes only running, unpaused tracks ([`events.c`](../external/irisEng/events.c#L1996-L2054)). An EVE AI-function event executes its serialized AI node program with a chosen owner/target context ([`events.c`](../external/irisEng/events.c#L168-L224)), so it can have arbitrary side effects. A decoded GAO/EVE link, an EOT candidate, a running track, and a track actually advanced by the game are distinct evidence levels.

8. **Jaded corroborates stop-all behavior and frame ordering, but not the BGE callback.** Its `TRAStopAll` wrapper calls `EVE_SetRunningTracks(..., FALSE)` ([`AIfunctions_tra.c`](../external/jaded/src/libraries/AIinterp/Sources/Functions/AIfunctions_tra.c#L50-L64)); this clears the running bit on each track without resetting its time or event cursor ([`EVEplay.c`](../external/jaded/src/libraries/AIinterp/Sources/Events/EVEplay.c#L260-L293)). In Jaded's world tick, EVE runs before animation and AI ([`ENGcall.c`](../external/jaded/src/libraries/ENGine/Sources/ENGcall.c#L230-L268)). This supports the generic meaning of `TRAStopAll`, but does not prove BGE's `Cine_Events` timer or exit-bit logic in Jaded. JadeView previews the configured finite timeout as an owner-wide stop; it does not currently model the earlier `0x4000` exit-bit branch, nor claim exact native frame-boundary timing.

## Deterministic archive state vs runtime/save state

| Can be resolved from archive keys and serialized data | Requires runtime or save context |
| --- | --- |
| GAO AI-instance key, AI model/variable keys, callback function keys, callback slot indexes, instance/model defaults and overrides | Which callback IDs the engine dispatches in the current update phase, and whether the callback's timer/state allows it to run |
| GAO EVE key, event-list reference, serialized event track content and literal targets | Whether the universe slot for that world is active, whether the object entered the EVE/EOT tables, current distance/sector eligibility, and `flags2` activation state |
| `Cine_Events` configuration variables, direct object references and serialized test parameters | Current special-save bits, active main actors, collisions/overlaps, capability state, interaction/input state, competing cinematic priority, and elapsed timers |
| Literal EVE calls and direct EVE animation/interpolation data | Arbitrary AI-function event behavior, callbacks dynamically added by running scripts, audio/device state and effects requiring game systems |

## JadeView implication

JadeView already has the safe foundation: [`PcScriptCallbackSlotReader`](../src/Features/Cinematics/Formats/Pc/PcScriptCallbackSlotReader.cs) preserves the five callback slots by function key; [`CinematicScriptOwnerResolver`](../src/Features/Cinematics/CinematicScriptOwnerResolver.cs) resolves an owner by exact world/key scope; and [`CinematicEventSchedulerAnalyzer`](../src/Features/Cinematics/CinematicEventSchedulerAnalyzer.cs) already reports EVE table activation as unproven instead of treating a linked resource as active.

The script-owner inspector now exposes a **generic owner-start lifecycle report**, keyed by `(world key, owner key)`, with collapsible archive-link, callback, world/EOT, start-predicate and EVE phases. Missing brain/model links remain partial; null callback resource sentinels are omitted. The separate start-gate evaluator uses only represented operands and labels save-state, active actor, collision, input, priority and activation-table dependencies as unresolved runtime gates. Custom-bit predicates can use serialized bits 8–15 and unambiguous known timeline writes; missing history, malformed setters and ambiguous ordering remain unknown. This is preview evidence, not proof of native execution.

The script-owned EVE preview also shows **Exit gates** at the current playhead. It can evaluate the configured saved-flag exit predicate from unambiguous timeline writes and the capability predicate from the object's evaluated preview capabilities. Exit collision and actor-activity predicates remain unknown because the preview does not have Iris's live collision result or runtime `flags2` bit 0. A satisfied snapshot means the represented predicates currently match; it does not invoke the callback, clear `0x4000`, or predict the frame on which `TRAStopAll` would run.

The start-gate panel also models the outer `Cine_Events_cine_tests_depart` branch: Iris calls `OBJ_CapaTest(0x100)` on the current owner before evaluating `i_tests_a_reussir` ([source](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L4557)). When the bit is set, that configured-predicate block is bypassed, but priority/interruption handling and the initialize/GoToEvents calls still follow; this does not mean the cinematic is already running. JadeView resolves this branch only when exactly one preview object matches the owner key and has evaluated `PreviewCapabilities`. Otherwise the branch and overall start result stay unknown. The UI reports the branch separately from the predicates and keeps activation and callback dispatch explicitly unproven.

The effective callback slot can enter this state machine through `Cine_Events_cine_firstinit`, not only through a direct assignment to `cine_tests_depart`. Iris source shows `firstinit → init → tests_depart`; callback slot 2 on retail owner `FF001FBE / 35009652` resolves to function key `26004C6C` (`Cine_Events_cine_firstinit`). JadeView now recognizes any of these source-linked startup-chain entry points when deciding whether to analyze configured start gates. This fixes the prior false “no effective callback slot” result for that owner. Its activity predicate and saved flag 2007 still remain unknown without the live target `flags2` and save state, and the assigned callback does not prove dispatch.

The same serialized owner and callback are also present in retail clip `35009F74` (`01_04_entrepot_liberation_mili_cine`). `--cinematic-owner-action-preview-audit` resolves zero Military body actions from the clip alone, then two `Action 201` segments (0–7.8167 s and 7.8167–19.8 s) when this owner is explicitly selected for preview. The owner is a normal-time initial-activation candidate and has one linked `SceneEvents` track, but its `Cine_Events` start gates remain unknown: Sally's runtime `flags2` activity bit must match `des_i_activity_test1`, and saved flag 2007 must be set. This establishes a serialized action path and a manual preview override; it does not establish that the game dispatched the callback or that either gate passed. The still-missing general evidence is the cross-scene/save-state provenance of flag 2007, plus live runtime state.

Zone predicates now expose their source-defined collision path instead of a generic “runtime input unavailable” message. Retail Iris resolves object selectors `1` and `2` as `AI_MainActor[0]` and `[1]`; they are dynamic actor references, not null sentinels (`ai_common.c:1579-1585`, `ai_compiledscripts_global_managers.c:4638-4773`). During `cine_init`, when `des_i_actor_type1` is nonzero, a null resolved `des_o_actor_zone1` is replaced with the current script owner ([init fallback](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L4223-L4258)). Therefore an unbound actor selector can take this owner-fallback path; JadeView reports it as conditional because it does not know the runtime `AI_MainActor` slots. `cine_tests_depart` calls `COLBVGetAllOverlaps` with object mask `0x20000` and, for actor types 1 or 2, filters the returned objects through one of two model predicates ([zone 1 filter](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L4617-L4708)). The Iris implementation of that helper reads the zone object's existing `detectionListGaos` and applies `OBJ_b_test_flag`; it does not calculate a fresh overlap set at the call site (`external/irisEng/ai/ai_colfunctions.c:88-117`). Thus archive collision shapes alone cannot establish the list contents at the time the callback runs. With no model filter, the callback uses `OBJ_FlagsIdentityTest(0x400)` to choose between `COLZDEPivotCollide` and `COLBVObjectObject` ([zone 1 collision branch](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L4710-L4779)). For zone 2, the same identity bit selects the collision API and `des_i_collision_type2` selects whether that result is required or inverted ([zone 2 branch](../external/irisEng/ai/ai_bge/ai_compiledscripts_global_managers.c#L4788-L4931)). The retail callback has no explicit special branch for serialized key `0xFFFFFFFF`; JadeView's archive-reference filter must not be confused with an Iris runtime interpretation.

The preview reports resolved zone/detector keys and the configured branch, but keeps both predicates **unknown**: static archive geometry and serialized object flags do not establish the live collision object set, runtime identity flag, or collision-query result. It does not simulate `COLBVGetAllOverlaps`, model identity in the live world, or pretend a loaded detector is overlapping a zone. `CinematicStartGateEvaluatorChecks` locks this boundary in tests.

The lifecycle report also exposes the shared `Cine_Events` serialized timing values: `f_first_delay` before `cine_init`, then `des_f_tempo` after the departure predicates pass. It resolves effective instance-over-model values and rejects malformed, negative, or non-finite numbers. Their sum is only the configured wait portion of startup: callback dispatch, readiness, gate/priority checks, runtime `f_timecode`, and EOT eligibility remain outside the archive preview. Automatic EVE scheduling does not shift tracks from these values alone.

When the user explicitly chooses a serialized flag/message start candidate for a script-owned `SceneEvents` preview, JadeView now estimates a start time as `max(signal time, f_first_delay) + des_f_tempo`, but only for a recognized `Cine_Events` owner with valid effective delays and `f_timecode == 0`. This follows the source sequence: first-init waits, then a passed departure test loads `des_f_tempo` into the wait timer before `GoToEvents`. The button tooltip labels this as an estimate; it does not predict callback dispatch cadence, message lifetime, readiness, actor/collision/priority gates, or actual runtime start. If required timing state is missing or nonzero/unknown, the preview retains the selected signal time instead. The user's manual **Preview** switch remains an explicit time-zero override.

Callback-reachable channels now expose the same configured-delay estimate as an explicit **Use configured start** preview override, with **Reset start to 0s** restoring the default. The estimate uses signal time 0, so it assumes the owner callback begins at the cinematic playhead origin; actual callback dispatch is not known. The override is applied through the shared nested-EVE timeline and therefore also affects GLB export. A channel already started independently by `RunningInit` keeps that earlier route and is not shifted by the callback override. Automatic scheduling still defaults to time zero until the owner has an explicit override, avoiding an unsupported assumption about when its AI callback becomes active.

Message-gated preview timing also joins decoded messages from `SceneEvents` EVE channels to the channels actually scheduled in the selected cinematic preview. It uses the matching message ID, configured `Int1` mask, queue object, event-list/channel identity, and the preview scheduler's mapped timeline time. The queue-owner comparison is accepted only when the current Iris EVE track-context model identifies a candidate; unresolved candidates are not used to move the preview start. This only aligns a user-selected preview start with a serialized signal that the schedule contains. It does not model queue capacity, dispatch order, message lifetime/consumption, or prove the retail game's runtime delivered that message.

This is present in retail archive data, not only in a synthetic fixture: `FF005520 / 3500A927` has a `Cine_Events` owner `3500AF96` with model `des_f_tempo=0` overridden by instance `des_f_tempo=1`; `FF0045A2 / 3500B8EA` has owner `3500BB66` with an instance override of `0.5`. These cases show why the effective instance value must be used when diagnosing apparent zero-time starts. They do not establish that either owner passed its gates in the original game.

Explicit cinematic preview remains a user-selected playback mode; loading does not invoke `cine_firstinit`, `InitialiseCine`, AI callbacks or arbitrary EVE function events. No sibling-name heuristic is needed for resolution, but archive data alone cannot determine that the native game would start a given cinematic. See `CinematicOwnerStartLifecycleChecks` and `CinematicStartGateEvaluatorChecks` for the bounded behavior.

## Scope and confidence

The `irisEng/ai/ai_bge` files contain BGE-specific compiled script bodies and are the strongest evidence here for `Cine_Events` behavior. IrisEng's engine code is a reconstructed engine source, and Jaded is a later Jade Engine source: it corroborates object/callback/event architecture, but does not prove every behavior of the 2003 PC binary. This audit describes source evidence and static/runtime boundaries, not a complete native VM emulation.
