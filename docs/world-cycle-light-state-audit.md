# World-cycle light state audit

## Finding

The world-cycle palette and cinematic light state are now connected for the supported fields. `CinematicWorldCyclePalette` samples phase colors from sun height and exposes ambient/RLI/fog/material values; `CinematicWorldCycleLightState` makes immutable sun/fog `SceneLight` overrides and composes them with literal cinematic light commands. The remaining gap is stateful moon illumination and other script-owned effects, not the already modeled sun/fog fields.

This is a missing connection between two already modeled state sources; it does not require scene-specific constants. Iris's `world_cycle_world_planetes` directly writes the same PC light component fields that the literal reducer supports.

## Source behavior with direct evidence

The source data structure `tScriptStruct_ENVWorldCycle` identifies the configured sun, moon, moon light, fog, sky, environment, and optional deactivation/standard-controller objects. It also stores the four height thresholds, normal and attack palettes, desired/current moon-light colors, attack coefficient, moon-relative light vector, and sun/moon phase timer/state (`external/irisEng/ai/ai_compiledscripts.h:3563-3622`). `CinematicEnvironmentReader` retains the environment/sky/fog/sun/moon/light/ray/deactivation/standard-controller references, palettes, thresholds, RLI factors, fog ranges, and attack speeds (`src/Features/Cinematics/CinematicEnvironmentReader.cs:6-62`).

`world_cycle_world_init` clears global flags 2718 and 2789, captures the moon-light offset in moon-local coordinates when both moon objects resolve, marks the configured deactivation object inactive, optionally copies configuration from `des_standard_world_cycle`, initializes the environment rotation from the world planet rotation, and starts tracking `world_cycle_world_cycle` (`external/irisEng/ai/ai_bge/ai_compiledscripts_global_mapmanager.c:5978-6041,6055-6078,6080-6422,6434-6454`). The global game loop calls `Global_glob_exec_world_cycle` on its normal update path (`external/irisEng/ai/ai_bge/ai_compiledscripts_global.c:546-551`). The world-cycle implementation is consequently a repeated runtime callback, not just a one-time palette lookup.

Each update samples the sun's world Z position against night, dawn, sunrise, and day thresholds (`...global_mapmanager.c:7029-7048,7054-7192`). The source behaviors relevant to diffuse preview are:

- Sun light active bit 3 is cleared below dawn, then set at sunrise and remains set through day/sunset (`...global_mapmanager.c:7054-7105,7145-7156,7192-7238`).
- Palette element 2 becomes the sun light's packed color; element 1 becomes fog light color (`...global_mapmanager.c:7436-7445,7481-7490`).
- Fog near/far use normal, attack, or a clamped linear interpolation according to `f_coef_attaque` (`...global_mapmanager.c:7363-7425`).
- Ambient channels use palette elements 0 and 5 only when the current owner lacks capability 256. RLI destination uses element 7 (`...global_mapmanager.c:7428-7435`).
- Palette element 6 drives the moon material constant; palette elements 3 and 8 drive the two environment constants; element 4 drives the sky constant and water color (`...global_mapmanager.c:7447-7480,7514-7524`). JadeView now maps palette element 6 to the configured moon's material constant key 0 (`src/Features/Cinematics/CinematicWorldCyclePalette.cs:61-64`).
- The moon light's position is recomputed by transforming the stored moon-local offset through the moon, adding moon position, and mirroring Z below dawn. Its color fades between zero and `des_c_moon_light`; the sun/moon phase state and elapsed time decide which direction the fade runs and when moon light bit 3 is cleared (`...global_mapmanager.c:7271-7361`). Its final packed color is written to the moon light (`...global_mapmanager.c:7525-7535`).
- The sun flare script color is separately set to an 80%-blend of sun color toward zero (`...global_mapmanager.c:7492-7513`). That is a script-owned appearance field, not the sun's diffuse `SceneLight` color.

The AI light helpers confirm these are mutations of the parsed light resource: `LightSetColor` requires an owner with identity flag `0x10` and a light component (`external/irisEng/ai/ai_lightfunctions.c:32-42`); `LightSetFlag` sets or clears `1 << bitIndex` under the same owner/component gate (`:211-229`); `LightSetNearFar` accepts types 0, 2, and 3 and updates each input independently only when nonnegative (`:57-96`). The current literal reducer already follows these field-level rules for its bounded literal inputs (`src/Features/Cinematics/CinematicLightStateTimeline.cs:10-13,116-153`).

## Current JadeView coverage and gaps

`CinematicWorldCyclePalette.Evaluate` selects phase palettes from sampled sun height, applies attack interpolation, returns fog color/range, RLI color/factor and ambient channels, and uses the capability-256 ambient gate (`src/Features/Cinematics/CinematicWorldCyclePalette.cs:9-60,81-150`). `CinematicAttackTimeline` derives the attack factor from literal global flag set/clear calls for flag 2718 and the controller's transition speeds (`src/Features/Cinematics/CinematicAttackTimeline.cs:3-47`); the Iris initializer confirms flag 2718 starts clear (`...global_mapmanager.c:5978-5979`).

The controller reader also retains named moon, moon-light, moon-ray, deactivation-object and standard-controller keys (`CinematicEnvironmentReader.cs:6-9,24-62`; `CinematicEnvironmentController.cs:5-13`). `CinematicWorldCyclePalette` writes the deterministic moon material constant from palette element 6. `CinematicWorldCycleLightState` samples the same palette helper and makes immutable sun/fog light overrides. The sun receives palette element 2 and the source active-bit transition (clear below dawn, set at/above sunrise; preserve baseline within the stateful dawn-to-sunrise interval with a diagnostic). The fog receives palette element 1 and the attack-interpolated near/far values, but only when the configured target resolves uniquely to a type-3 light. Moon-light position/fade/active state remains unresolved and produces a diagnostic when moon-light objects are configured. The evaluator does not guess targets by object name.

`CinematicPlayback.Advance` and `Seek` evaluate actors first, then attack/material and the world-cycle light snapshot, and finally compose that immutable snapshot with the literal light timeline (`CinematicPlayback.cs:355-375`). `CinematicWorldCycleLightState.Compose` applies cycle fields first and literal fields second, so non-overlapping fields combine and only colliding receiver/field pairs emit `LiteralOrderingApproximation`. Source `SceneLight` objects remain untouched. The same `LightState` snapshot is consumed by the viewport and passed to the static GLB sample path. Tests are in `CinematicWorldCycleLightStateChecks` and `CinematicLightStateTimelineChecks`.

## Generic implementation path

1. Reconstruct moon-light position only when initialization transforms are known; otherwise expose the computed local-offset recipe and report that the original initializer pose is unavailable. Reconstruct moon-light color/active state only with an explicit initial `i_soleil_ok`, `c_moon_light`, and `f_time_moon` plus timeline transitions. Do not infer its timer or fade direction from current sun height alone.
2. Add a separate `SFXSun` type-18 effect snapshot and renderer using the resolved script configuration/material; the palette-derived color and owner position are available, while native occlusion history remains an explicit approximation (details above).
3. Add retail/runtime captures for the stateful sunrise hysteresis and same-frame owner ordering. The static code does not reveal scheduler order between the global world-cycle callback and all clip callback owners.

## Ordering boundary

Iris evidence shows that world-cycle writes run in the global update path and that cinematic literal calls are also represented as a separate time-sorted prefix in JadeView. The source repository does not expose a shared per-frame scheduler order between a world-cycle callback and every cinematic owner's callback. Therefore exact same-frame last-writer order cannot be claimed from these sources alone.

For a deterministic editor snapshot, compute the world-cycle base first and apply the bounded literal timeline second, so explicit time-stamped calls remain visible as overrides; report collisions on the same receiver/field as an ordering approximation. A later scheduler/owner execution model can replace that precedence once it can establish callback order. This also avoids mutating source `SceneLight` instances and remains deterministic when seeking backward.

## Moon initializer and fade: static/runtime split

The moon-light position has a reproducible initializer, but only from the objects' transforms at world-cycle initialization. `world_cycle_world_init` first requires both `des_o_moon_light` and `des_o_moon`; it reads their world positions, forms `moonLightWorld - moonWorld`, converts that vector into the moon's local space, stores it in runtime field `v_rel_lune_lgt`, and calls `OBJ_HierarchyReset` on the light (`external/irisEng/ai/ai_bge/ai_compiledscripts_global_mapmanager.c:5980-6052`; the field is declared at `external/irisEng/ai/ai_compiledscripts.h:3618-3620`). On every update the callback transforms that stored local vector through the current moon, adds the moon world position, mirrors the resulting Z when it is below the dawn threshold, and writes the moon-light position (`...global_mapmanager.c:7271-7322`). Thus a deterministic static reconstruction is possible if the exact initialization transforms and transform conventions are available. Reusing the current preview transforms is only valid if those still equal the state when the initializer ran.

There is an important transform-version boundary. Iris's helper calls the absolute-matrix global/local vector transforms (`external/irisEng/ai/ai_mathfunctions.c:1139-1145,1164-1170`). The available Jaded implementation has an extra hierarchy-aware branch: it calls `OBJ_ComputeGlobalWithLocal` while the identity hierarchy flag is set, otherwise uses the absolute matrix (`external/jaded/src/libraries/AIinterp/Sources/Functions/AIfunctions_mth.c:701-720,743-762`). Iris then resets the moon-light hierarchy after capturing the offset; Jaded's reset clears the hierarchy identity bit and removes the object from the hierarchy table (`external/jaded/src/libraries/AIinterp/Sources/Functions/AIfunctions_obj.c:5591-5631`; Iris equivalent `external/irisEng/ai/ai_gameobjectfunctions.c:2832-2860`). Jaded confirms the engine-level operation shape, but is an earlier source tree and cannot settle the retail PC transform result on its own.

The fade is stateful, not a direct function of current sun height. `i_soleil_ok` selects day/sun versus night/moon mode. When a callback crosses into night/dawn it records `f_time_moon` only on a transition from the sun mode, then clears `i_soleil_ok`; when it crosses into sunrise/day it records the time only on the opposite transition and sets the flag (`...global_mapmanager.c:7067-7109,7145-7161,7192-7208,7227-7243`). Each update computes elapsed global time minus that transition timestamp. In sun mode it blends `des_c_moon_light -> 0` and disables moon-light flag bit 3 after the resulting color reaches zero; in moon mode it enables bit 3 and blends `0 -> des_c_moon_light` (`...global_mapmanager.c:7323-7361`). `des_c_moon_light` is the configured target color at struct offset 440, while current `c_moon_light`, `f_time_moon`, and `i_soleil_ok` are runtime fields at offsets 600, 648, and 652 (`external/irisEng/ai/ai_compiledscripts.h:3600,3613,3620-3622`). The initializer function does not assign those three runtime fields; the available static sources do not establish whether retail instance construction seeds them from saved script state or zeros them. Therefore a seek into an already-running world cannot infer the fade from the sun height alone; it needs an initial-state policy or captured runtime state and transition history.

Iris clamps `COLOR_Blend`'s factor to `[0,1]` and uses its packed-color interpolation helper (`external/irisEng/ai/ai_materialandcolorfunctions.c:1039-1045`). Jaded's earlier helper instead unpacks channels, linearly interpolates normalized RGBA, then repacks (`external/jaded/src/libraries/AIinterp/Sources/Functions/AIfunctions_COLOR.c:162-191`). For retail-oriented preview, follow Iris's implementation; Jaded's algorithm is useful engine context, not evidence that the later PC build blends identically.

## SFXSun and GFX type 18

`world_cycle_world_cycle` computes the SFX sun color independently from the light component: it blends final palette color 2 toward black at factor `0.8`, then writes `c_Color` into the AI instance attached to `des_o_sun` (`external/irisEng/ai/ai_bge/ai_compiledscripts_global_mapmanager.c:7492-7513`). The struct layout gives the field names and offsets (`external/irisEng/ai/ai_compiledscripts.h:3539-3561`). `SFX_Sun_loop` only keeps an effect alive while `c_Color != 0`; on first creation it adds GFX type `18`, binds `des_o_source_mat` plus `des_i_NoMat` as its material/submaterial, and enables GFX flag 2. Every callback sends owner position as parameter 18200, `f_Interval` as 18011, `f_Time` as 18012, `Distance` as 18013, `LRatio` as 18010 and `c_Color` as 18102. When its compute flag is set, it additionally sends ray geometry parameters from `Balpha`, `BLMin/BLMax`, `BWMin/BWMax`, `Salpha`, `SLMin/SLMax`, `SWMin/SWMax`, `i_Number`, `i_Hide`, then sets 18100 to recompute ray layout. Owner capability 2 is sent as parameter 18104 (`external/irisEng/ai/ai_bge/ai_compiledscripts_sfx.c:6661-6735`). Struct fields beginning `des_` are explicit configured references; the source names the other values as instance fields, but these C files alone do not prove which ones are stored in default-vs-instance OVA records or their values for any particular archive.

Jaded names the GFX type-18 parameters in `external/jaded/src/libraries/GraphicDK/Sources/GFX/GFX.h:208-213,477-498`: `18000-18009` are big/small ray angular tolerance, length and width ranges; `18010` length ratio; `18011` visibility-test point interval; `18012` hide/fade time; `18013` distance. `18100` recomputes rays, `18101` is count, `18102` packed color, `18103` flags, `18104` death; `18200` is the position. The retail Iris setter tables and struct offsets are consistent: float setters map to fields beginning at offset `0x0C`, integer setters map compute/count/color/flags/death to `0x4000`, `0x48`, `0x4C`, `0x50`, and byte offset `0x54`, respectively (`external/irisEng/gfx.c:30-60,1119-1160,1180-1205`; the retail struct is `external/irisEng/gfx/gfxsun.h:31-63`). This confirms 18104 is the one-byte death switch and 18100 invokes `GFX_Sun_ComputeRay`, rather than being generic flags or animation controls.

The rendered object is generated camera-facing geometry, not a textured sky dome. Iris `GFX_Sun_Render` creates `num` triangles, assigns one three-vertex UV wedge per ray, interpolates packed color across eight visibility sectors, constructs each wedge from the camera's right/up axes and the configured ray lengths/widths, and renders the temporary geometry (`external/irisEng/gfx/gfxsun.c:712-1134`). `GFX_Sun_ComputeRay` pairs big and small rays around a circle with independent random angular jitter and length/width ranges (`:30-140`); GFX creation supplies defaults, including 32 rays, 0.2 angular tolerances, 10–15/1–2 big-ray length/width, 2–4/2–3 small-ray length/width, ratio 3, interval 1, hide time 0.1 and distance 10 (`:230-265`). The script callback then supplies its instance parameters. The standard source flags include depth-size, hidden state and hide/visibility-test mode; Jaded names their bits in `external/jaded/src/libraries/GraphicDK/Sources/GFX/GFXflare.h:23-44` and renders Sun as GFX type 18 in `GFX.c:854,1043`.

Visibility is stateful and sampled, not a simple camera-facing billboard test. Iris's PC/DX9 path tests the projected sun center and visibility texture/surface data, carries a nine-bit center/eight-sector mask between frames, and drives per-sector luminance toward the visibility target over time (`external/irisEng/gfx/gfxsun.c:643-710,830-841,874-1042`). Jaded's software path instead samples a projected center and eight nearby screen points through its read-pixel request and smooths the same eight luminance sectors (`external/jaded/src/libraries/GraphicDK/Sources/GFX/GFXflare.c:1014-1096,1151-1297`). The two source trees agree on the effect's broad mechanism, but their occlusion backends differ; native PC output specifically depends on the Iris DX9 visibility/blur surfaces and cannot be exactly reconstructed from the older Jaded fallback alone.

### JadeView overlap and implementation seam

JadeView currently has a ray drawing helper, but it is attached to a different source behavior: `CinematicFlashReader` selects `SFX_Flash` (`src/Features/Cinematics/CinematicFlashReader.cs:3-45`) and `SceneRenderer.Cinematics.ResolveCinematicFlashTexture` binds that behavior's `SFX_light&smoke.gao` submaterial 11 (`src/Features/SceneEditor/SceneRenderer.Cinematics.cs:227-246`). `CinematicSunRayLayout` uses deterministic seeded jitter and a viewport radius cap (`src/Features/Cinematics/CinematicSunRayLayout.cs:7-43`); `DrawCinematicFlashes` screen-projects the position, draws additively, and performs a front-of-camera test, but does not run Iris's center/eight-sector visibility sampling or time-smoothed occlusion (`src/Features/SceneEditor/SceneRenderer.Cinematics.cs:189-225`). Therefore the current flash renderer may be reusable for triangle construction, but its hardcoded material and opacity/visibility behavior must not be treated as the source `SFXSun` implementation.

The bounded generic path is to discover `SFX_Sun_loop` owners from the script model and read their source material reference, submaterial index, and ray configuration into an effect snapshot; use the already evaluated world-cycle palette color 2 to derive its `c_Color`; take position from the resolved owner at the current cinematic sample; and render a type-18 ray mesh with that owner-specific material. Keep it separate from sun `SceneLight` diffuse, world-cycle sky/fog, and `SFX_Flash` events. Do not force the effect on from the controller palette alone: in source it exists only when the sun-script callback has a nonzero `c_Color`, receives owner position/color/parameter updates, and may be hidden or dying according to script state and visibility results.

The deterministic part available to an offline cinematic snapshot is the packed flare color plus configured geometry parameters when their script defaults/instance values resolve, and the owner's sampled position. Source does not provide a pure time-to-visibility function: native visibility depends on rendered depth/blur surfaces, previous per-sector luminance, frame delta, prior position, hide/death state, and callback order. Until JadeView has a depth-sampling/effect history model or runtime captures, it can render the source-shaped rays but must label visibility/transition as an approximation rather than claim native parity.

## Deliberate limits

The current world-cycle light snapshot applies only the source-confirmed sun and type-3 fog fields. The palette/material path also applies the moon's material constant, but moon-light color, position, near/far, and active-state evaluation remain unimplemented because initialization transforms and stateful fade inputs are not reconstructed. The derived SFX sun-flare color is understood, but its GFX effect is not yet part of the light snapshot or renderer. The light snapshot also cannot reproduce the global water setter, world-cycle deactivation/visibility callbacks, teleport-driven planet motion, or game callback scheduling. These remain separate environment/effect state rather than reasons to special-case individual maps.
